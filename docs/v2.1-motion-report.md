## 动效系统

- **全站文字**：标题、正文、标签和数据按进入视口编排；短 mono 标签以原位 glyph decode 呈现，读屏只读取一份真实文本。
- **真实图片**：照片、教材、证书、Logo 与小 A 使用五色遮罩、边缘扫描、短 glitch、透视 tilt 和有界同图残影；效果结束后原图清晰完整。
- **分区记忆点**：About 时间线流动；AI 学习信号、教材轨道与九宫格分波；Singapore 标签均匀启动；理念逐词显影并以小 A 收尾；Contact 卡片与链接依次进入；Footer Logo 完成五色 bloom。
- **桌面 pointer**：`FinePointer` 只在精细指针且宽度大于 820px 时启用，五色 Canvas 轨迹、卡片景深和导航磁吸共用一套 pointer 状态。
- **生命周期**：新增 pointer 动效使用**单一 requestAnimationFrame 调度器**，Hero 与既有计数器保留各自生命周期；页面隐藏时暂停并复位 hover/残影，图片未解码时不生成残影。

## 移动端与无障碍

- 移动端关闭自定义光标、图片残影与 3D tilt，同时关闭强 glitch；保留轻量进入与清晰的中英信息层级。
- `prefers-reduced-motion` 由自动化契约检查：不拆字、不位移、不播放残影/glitch/循环，所有内容直接显示最终状态。本轮 in-app browser 未直接模拟该 OS 媒体条件，因此不把静态契约写成浏览器实测。
- 动态拆字使用屏幕阅读器专用真实文本，动画 glyph run 设为 `aria-hidden`，避免重复朗读。
- 移动菜单可用键盘操作，Esc 关闭并归还焦点；focus-visible 样式继续保留。

图片残影使用固定池并限制尺寸、数量与寿命；不为每个元素创建永久循环。`IntersectionObserver` 负责一次性入场，pointer 与需要持续更新的状态统一进入共享帧循环。

## GitHub 调研落地

- [tsParticles](https://github.com/tsparticles/tsparticles)：借鉴失焦暂停、视口生命周期、帧率与 Retina 上限，不引入其依赖。
- [particles.js](https://github.com/VincentGarreau/particles.js)：借鉴密度与短连接的视觉语法，保留项目语义 token。
- [Pts](https://github.com/williamngan/pts)：借鉴 update/draw 分离，落为原生共享调度器。
- [AOS](https://github.com/michalsnik/aos)：借鉴一次性 reveal 与移动端差异化，继续使用现有 `IntersectionObserver`。
- [W3C WCAG](https://github.com/w3c/wcag)：落实可暂停动画、键盘焦点与 reduced-motion 静态退化。

以上仓库只用于模式研究；没有复制第三方实现代码或引入第三方许可证负担。

## 部署与回滚

发布：最终测试通过后执行 `git push origin main`，由 **Cloudflare Pages** 自动部署到 `https://bloomingfuture.io`。线上核对 `motion.js?v=2.1.0-r4`、三份 motion 资源、首页滚动、图片加载和 console。

回滚：执行 `git revert <release-commit>` 生成可审计的反向提交，再执行 `git push origin main`；禁止 force push。
